# Creative web production

Use this with [creative-production](../creative-production/SKILL.md) for the shared experiment workflow and the relevant BOUCH lessons.

## Shape the work

- Establish the audience, purpose, content, desired feeling and the user's actual identity or evidence to express. A polished generic company site is not a successful personal portfolio if it does not feel personal.
- If the direction is open, create a small set of clearly different concepts before committing. Explore distinct premises, visual languages or information structures—not minor palette changes. Use references to widen the vocabulary and explain what was inspected; do not copy a site or assume a popular technique fits.
- Set practical content and asset constraints early. Use real project evidence where available; label invented data and placeholder claims visibly. Avoid writing personal credentials, results or public claims without evidence.
- Choose interaction and motion for a clear role in the experience. An unusual interaction can make the work memorable, but it must not overwhelm the subject matter or become a metaphor that narrows the whole site.

## Build and review

- Produce a working, navigable draft with editable source. Review the rendered page at useful desktop and mobile widths, including actual interactions and content—not only a screenshot or the code.
- Use Playwright or browser automation to exercise links and states, keyboard access, responsive behavior, console/network errors and basic page health when available. Use Chrome DevTools for focused runtime inspection. Confirm which agent has the tools; a supervisor's access does not imply the builder's.
- Check semantic structure, focus visibility, contrast, text scaling, reduced motion, loading behavior and overflow. Use automated accessibility checks as a signal, then inspect meaningful keyboard and screen-reader behavior where relevant.
- Compare the built result to the chosen direction and the user's purpose. Correct concrete shortcomings and keep rejected directions available when comparative review is still useful.
- Before handing off, explain how to run the study, list what was verified and what remains untested. Do not deploy or publish unless that is part of the user's request.
